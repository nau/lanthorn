## Token refresh

*Informative.* A client trades a refresh token for a new access token and a new refresh token. Each refresh token works once, because the auth service revokes it during the trade. A second use of a refresh token means that someone copied it, so the auth service revokes every token in that family.

- The auth service MUST issue a new refresh token on every successful refresh. `[auth.rotate]`
- The auth service MUST revoke the presented refresh token before it returns the new refresh token. `[auth.revoke-before-return]`
- The auth service MUST revoke the whole token family when a client presents an already revoked refresh token. `[auth.family-revoke]`

**Why:** `[auth.rotate]` and `[auth.revoke-before-return]` together make a stolen refresh token single-use. Rotation without revocation leaves both tokens valid, so a thief and the client can both keep refreshing without detection. `[auth.family-revoke]` turns the replay of a revoked token into a detected theft instead of a rejected request. It also cuts off the thief's newer tokens, because they belong to the same family.
