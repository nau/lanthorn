## Token refresh

*Informative.* A client trades a refresh token for a new access token and a new refresh token. Each refresh token works once, because the auth service revokes it during the trade. A second use of a refresh token means that someone copied it, so the auth service revokes every token in that family.

- The auth service MUST issue a new refresh token on every refresh. `[auth.rotate]`
- The auth service MUST revoke the presented refresh token before it returns the new one. `[auth.revoke-before-return]`
- The auth service MUST revoke the whole token family when a client presents an already revoked refresh token. `[auth.family-revoke]`

**Why:** `[auth.rotate]` and `[auth.revoke-before-return]` together make a stolen refresh token single-use. `[auth.family-revoke]` turns the replay of a stolen token into a detected theft rather than a rejected request. Rotation without revocation leaves both tokens valid, so the theft stays invisible.
