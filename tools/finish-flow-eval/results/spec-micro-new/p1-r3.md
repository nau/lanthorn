## Token refresh

*Informative.* A client trades a refresh token for a new access token and a new refresh token. Each refresh token works once, because the auth service revokes it during the trade. A second use of a revoked refresh token means that someone copied it, so the auth service revokes every refresh token in that token family.

- The auth service MUST issue a new refresh token on every successful refresh. `[auth.rotate]`
- The auth service MUST revoke the presented refresh token before it returns the new refresh token. `[auth.revoke-before-return]`
- The auth service MUST revoke every refresh token in the token family when a client presents an already revoked refresh token. `[auth.family-revoke]`

**Why:** `[auth.rotate]` and `[auth.revoke-before-return]` together make each refresh token single-use. Rotation without revocation leaves both tokens valid, so a theft stays invisible. `[auth.family-revoke]` turns the replay of a stolen refresh token into a detected theft instead of a rejected request. It also cuts off the thief and the client in the same family, so the user must authenticate again.
