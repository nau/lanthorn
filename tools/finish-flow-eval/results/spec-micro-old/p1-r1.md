## Token refresh

*Informative.* A client trades a refresh token for a new access token and a new refresh token. Each refresh token works once, because the auth service revokes it during the trade. A second use of a refresh token means that someone copied it, so the auth service revokes every token in that family.

**Who:** The client that holds a refresh token.

**Trigger:** The client presents a refresh token to the auth service.

**Structure:**

| Direction | Field | Type |
|---|---|---|
| Input | refresh token | opaque string |
| Output | access token | string |
| Output | refresh token | opaque string |

**Checks enforced here:**

- The auth service MUST issue a new refresh token on every successful refresh. `[TR-1]`
- The auth service MUST revoke the presented refresh token before it returns the new refresh token. `[TR-2]`
- The auth service MUST revoke the whole token family when a client presents a refresh token that is already revoked. `[TR-3]`

**Why:** `[TR-1]` and `[TR-2]` together make a refresh token single-use. Without `[TR-2]`, the old and new tokens are both valid, so a stolen token stays usable. `[TR-3]` turns the replay of a stolen token into a detected theft instead of a rejected request.

**Checks delegated elsewhere:** None.
