## Token refresh

*Informative.* A client trades a refresh token for a new access token and a new refresh token. Each refresh token works once, because the auth service revokes it during the trade. A second use of a refresh token means that someone copied it, so the auth service revokes every token in that family.

**Who:** The client that holds a valid refresh token.

**Trigger:** The client presents a refresh token to the auth service.

**Structure:**

| Direction | Field | Type |
|---|---|---|
| Input | Refresh token | Opaque string |
| Output | Access token | String |
| Output | New refresh token | Opaque string |

**Checks enforced here:**

- The auth service MUST issue a new refresh token on every successful refresh. `[TR-1]`
- The auth service MUST revoke the presented refresh token before it returns the new one. `[TR-2]`
- The auth service MUST revoke the whole token family when a client presents an already revoked refresh token. `[TR-3]`

**Why:** `[TR-1]` and `[TR-2]` together make a stolen refresh token single-use. `[TR-3]` turns the replay of a stolen token into a detected theft rather than a rejected request. Rotation without revocation leaves both tokens valid, so the theft stays invisible.
