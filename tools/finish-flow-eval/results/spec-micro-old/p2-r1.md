# Decision: grace period for a reused refresh token

## Overview

*Informative.* A client trades a refresh token for a new access token and a new refresh token. The auth service revokes the old refresh token during the trade. If a client loses the response, it retries with the old token. The auth service sees a revoked token and normally treats it as theft. With the grace period, the auth service accepts a reuse within 10 seconds of the revocation as a retry, so it does not revoke the token family. A reuse after 10 seconds is still treated as theft, and the auth service revokes the whole family. No client changes.

## Goals and non-goals

*Informative.*

**Goals**

- A client that loses a refresh response can retry without losing its session.
- Every existing client keeps working without a change.

**Non-goals**

- Exact separation of a retry from a replay. A replay within the grace period is not detected as theft.
- A per-client retry token.
- Any change to the client.

## Approaches

*Informative.*

| Approach | Trade-off | Result |
|---|---|---|
| Grace period of 10 seconds for a reused refresh token | Needs no client change. It is not exact: a stolen token replayed within the grace period looks like a retry. | **Chosen** |
| Per-client retry token | Exact: the auth service can tell a retry from a replay. Every client must change. | Rejected |

**Why the grace period won:** The retry token is exact, but its cost is a change in every client. The grace period costs one short window of weaker theft detection and needs no client change. The decision accepts that window `[A-1]`.

## Assumptions

- A client that loses a refresh response retries within 10 seconds. Clients make this true. A retry after the grace period is treated as theft. `[A-1]`

## Definitions

- **refresh token**: a single-use credential that a client trades for a new access token and a new refresh token.
- **token family**: all refresh tokens that descend from one original refresh token.
- **grace period**: 10 seconds, measured from the time the auth service revokes a refresh token.
- **grace reuse**: the presentation of a revoked refresh token within the grace period.

## Token refresh

**Overview.** *Informative.* The auth service revokes the presented refresh token and records the time. If the same token arrives again within 10 seconds, the auth service treats it as a retry and leaves the family alone. If it arrives later, the auth service revokes the family.

**Who.** The client that holds the refresh token.

**Trigger.** The client presents a refresh token that the auth service has already revoked.

**Structure.**

| Field | Direction | Type |
|---|---|---|
| Refresh token | Input | string |
| Response to a grace reuse | Output | See Open questions |
| Response to a reuse after the grace period | Output | Rejection, with the token family revoked |

**Checks enforced here.**

- The auth service MUST record the time at which it revokes a refresh token. `[TR-1]`
- The auth service MUST treat a presented revoked refresh token as a grace reuse when 10 seconds or less have passed since its revocation time. `[TR-2]`
- The auth service MUST NOT revoke the token family on a grace reuse. `[TR-3]`
- The auth service MUST revoke the whole token family when a presented revoked refresh token was revoked more than 10 seconds ago. `[TR-4]`

*Example, illustrative.* A refresh token is revoked at t = 0:

| Time of reuse | Result |
|---|---|
| t = 4 s | grace reuse, family kept |
| t = 10 s | grace reuse, family kept |
| t = 11 s | family revoked |

**Why:** `[TR-1]` gives `[TR-2]` and `[TR-4]` a start time to measure from. `[TR-3]` removes the need for a client change, because a client that retries after a lost response keeps its session. `[TR-4]` keeps theft detection for every reuse outside the window. The cost is that a stolen token replayed within the window is not detected `[A-1]`.

**Checks delegated elsewhere.** None.

## Open questions

- What does the auth service return on a grace reuse: the same new token pair as the first trade, or a rejection that leaves the family intact? `[TR-3]` fixes only that the family is kept. Still open.
