## Decision: grace period for a reused refresh token

*Informative.* A client that loses the response to a refresh presents the same refresh token a second time. The auth service cannot tell this retry from a replay of a stolen token. The auth service therefore allows a 10-second grace period after revocation. Within it, a reused refresh token is not treated as theft.

### Approaches

*Informative.*

| Approach | Trade-off | Result |
|---|---|---|
| Grace period of 10 seconds | Needs no client change. It is not exact: a replay of a stolen token inside the grace period is not detected. | Chosen |
| Per-client retry token | Is exact, because the auth service can tell a retry from a replay. Every client must change. | Rejected |

**Why:** The grace period ships without a client release. The exact retry token costs a change in every client. The accepted loss is a 10-second window in which a replay goes undetected.

### Checks enforced here

- The auth service MUST accept a reused refresh token for 10 seconds after it revoked that token. `[TR-5]`
- The auth service MUST NOT revoke the token family when a reused refresh token arrives inside the grace period. `[TR-6]`
- The auth service MUST revoke the whole token family when a reused refresh token arrives after the grace period. `[TR-7]`

*Example, illustrative.* The auth service revoked a refresh token at server time 1700000000.

| Server time of the second use | Result |
|---|---|
| 1700000009 | inside the grace period, family stays valid |
| 1700000010 | inside the grace period, family stays valid |
| 1700000011 | after the grace period, family revoked |

**Why:** `[TR-6]` and `[TR-7]` together keep theft detection, with a bounded blind spot. After 10 seconds, a replay still revokes the family. `[TR-5]` makes the retry from a lost response succeed.

### Checks delegated elsewhere

None.

### Open questions

*Informative.*

- The boundary at exactly 10 seconds is decided by `[TR-5]` and the example: the grace period includes second 10.
- Still open: what the auth service returns for a reused refresh token inside the grace period. The options are a new token pair or a plain rejection without family revocation. `[TR-5]` and `[TR-6]` do not decide it.
