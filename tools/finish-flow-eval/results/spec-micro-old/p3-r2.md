## Token refresh

- The token service MUST issue a new refresh token on every refresh. `[TR-1]`
- The token service MUST revoke the presented refresh token before it returns the new one. `[TR-2]`
- The token service MUST revoke the whole family on reuse of a revoked token. `[TR-3]`
- The token service MUST reject a refresh token whose age is more than 30 days, measured from the time the token service issued it. `[TR-4]`

*Example, illustrative.* For `[TR-4]`, a refresh token issued at time T:

| Server time | Result |
|---|---|
| T + 29 days | accept |
| T + 30 days | accept, the age is not more than 30 days |
| T + 30 days + 1 second | reject |

I made two readings of "older than 30 days" that you should confirm:

- **Age counts from issue time.** The age of a token is measured from when it was issued, not from when its family began. If you want a limit on the whole family, the rule needs different wording.
- **Exactly 30 days is accepted.** "Older than" means strictly more, and the example shows this boundary.

I appended the rule as `[TR-4]` instead of placing it first, so the published IDs `[TR-1]` to `[TR-3]` stay stable. The list order does not imply a check order.
