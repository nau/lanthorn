## Token refresh

- The token service MUST issue a new refresh token on every refresh. `[TR-1]`
- The token service MUST revoke the presented refresh token before it returns the new one. `[TR-2]`
- The token service MUST revoke the whole family on reuse of a revoked token. `[TR-3]`
- The token service MUST reject a refresh token that is more than 30 days old, counted from the time the token service issued it. `[TR-4]`

*Example, illustrative.* With a refresh token issued at `T`:

| Server time | Result |
|---|---|
| `T` + 30 days - 1 second | accept |
| `T` + 30 days | accept, the token is not yet older than 30 days |
| `T` + 30 days + 1 second | reject |

**Why:** `[TR-4]` limits how long a stolen refresh token stays usable, even if its owner never presents it again.

- "Older than 30 days" had no starting point, so I chose the issue time of that token. If you mean the first token in the family, `[TR-4]` and the example need to change.
- "Older than" put exactly 30 days on the accept side. Tell me if you want the boundary to reject.
