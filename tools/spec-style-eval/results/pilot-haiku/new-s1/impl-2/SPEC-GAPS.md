- GAP: Whether a deposit holding native tokens or other assets may leave with the host, since the validator reads only lovelace of the own input and the spec does not say what happens to other assets in the deposit | CHOSE: Release, Cancel and Claim ignore other assets entirely; the spec's assumption [A-5] (app locks ADA only) is taken as the boundary, and no token check was added.
- GAP: Which inputs count as deposit inputs when two inputs share the script credential but have different datums or references | CHOSE: any input whose address credential equals the own input's credential counts as a deposit input, regardless of datum.
- GAP: How the own input's credential is matched to "the payment credential of the deposit script" | CHOSE: the own input's full payment credential (its script hash, taken from the input being spent) is used as the deposit script credential; no separate script hash is hard-coded.
- GAP: Whether the redeemer and datum decode failures are distinct from a check failure (for example, an unknown redeemer constructor) | CHOSE: a failed decode of the datum or the redeemer fails the script, as [SP-2] and [SP-3] require; no other handling.
- GAP: The validity range may be empty or inverted (L greater than U), and the spec does not say whether that is an error | CHOSE: the validator applies only the time rules of each action, so an inverted range is accepted when the time rules hold; the ledger's own range handling is trusted, as in [A-2].
- GAP: Whether a host output with a staking part counts toward the host output sum, and whether the guest output sum must match the guest's full address | CHOSE: the definitions in the spec are followed exactly: only the payment key hash is compared and the staking part is ignored, so a payout to the guest's key with any staking part counts.
- GAP: Whether the deposit lovelace can be zero or negative, and what the fee is then | CHOSE: the fee is clamped to the deposit as [CA-11] requires, so a zero deposit gives a zero fee and [CA-13] then requires a zero host sum; a negative deposit is not reachable on the ledger and is not checked.
- GAP: Whether the rate in the fee formula is clamped to the range 0 to 5000 before or after the minimum fee is applied, when feeBps is negative | CHOSE: the order of [CA-7] to [CA-11] is applied literally: cap at 5000, then clamp negatives to 0, then the rounding, the minimum, and the deposit cap.
